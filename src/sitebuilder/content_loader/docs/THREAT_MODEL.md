# THREAT_MODEL — content_loader

## 자산
- 로컬 파일시스템의 `data/`, `content/` 디렉터리 바깥에 있는 파일들 (읽기 노출 방지 대상)

## 위협
1. **경로 순회 (Path Traversal)**: 콘텐츠 slug/파일명에 `../`가 포함되어 base 디렉터리 밖의
   파일을 읽거나 나중에 렌더러가 밖의 경로로 쓰게 되는 경우.
   - 대응: 모든 로더 함수는 `resolve()` 후 base 디렉터리의 하위 경로인지 검증하고, 아니면
     `ContentLoadError`를 발생시킨다. 테스트: `test_loader.py::test_rejects_path_outside_base_dir`.
2. **YAML 역직렬화 공격**: `yaml.load`(safe하지 않은 로더) 사용 시 임의 Python 객체 생성 가능.
   - 대응: `yaml.safe_load`만 사용. 코드 리뷰 시 `yaml.load(` 사용 여부를 grep으로 확인.
3. **거대 입력으로 인한 자원 고갈**: 매우 큰 Markdown/YAML 파일로 인한 메모리 과다 사용.
   - 대응: 개인 포트폴리오 규모(로컬 신뢰 입력)라 우선순위 낮음. 향후 외부 기고 콘텐츠를 받는
     기능이 생기면 파일 크기 상한을 추가한다 (지금은 범위 밖).

## 신뢰 경계
- 콘텐츠 파일은 저장소 소유자(사용자)만 작성한다고 가정 (신뢰된 입력). 외부 사용자가 콘텐츠를
  제출하는 기능(예: 방명록)이 추가되면 이 문서를 갱신하고 신뢰 경계를 다시 정의해야 한다.
